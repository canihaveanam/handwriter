# 手写大病历生成器 (handwriter)

## 一句话说明

一个内网小工具：用户在网页文本框里输入病历文字，后端用手写字体渲染成 PDF（叠加在扫描的病历纸背景图上），可以在线预览，也可以打包成一批 JPG 图片下载。同时支持保存一份"共享模板"，让局域网内所有人打开网页都能看到同一份草稿内容。

## 给 AI 看的须知

如果你（AI）在帮我改这个项目：
- 后端是 **Flask 单文件应用**，所有路由都写在 `app.py` 里，没有拆分蓝图/多文件，改动时直接改 `app.py` 即可。
- 前端是 **纯 HTML + 原生 JS**，`index.html` 一个文件，没有构建工具、没有框架（不是 React/Vue），所有交互靠 `<script>` 里的原生函数 + `fetch`。
- 部署方式是 **打包成单个 exe（PyInstaller），放在内网某台电脑上跑，用户局域网访问**，不是部署在云服务器上，因此“重启后数据是否还在”“文件存在哪”是经常要考虑的问题。
- 只有**一个共享模板**，不是多模板列表管理，别把它想复杂了。
- 目前**没有数据库**，所有持久化都是本地 JSON / 文本文件。
- 目前**没有登录鉴权**，局域网内任何人都能访问、修改模板、生成病历。

```

├── index.html           # 前端全部代码（HTML + CSS + JS 都在这一个文件里）
├── base.jpg              # 病历纸背景图，PDF 每页都会先画这张图再叠文字
```

## 运行环境 / 依赖

- Python 3.x + 虚拟环境（`venv/`）
- 主要第三方库（对应 `requirements.txt`）：
  - `flask` — Web 框架
  - `reportlab` — 生成 PDF、注册手写字体、逐字绘制文字
  - `pymupdf`（导入名 `fitz`） — 把生成好的 PDF 转成 PNG 图片（用于打包下载 ZIP）
  - `pillow`（导入名 `PIL`） — 图片格式转换（PNG → JPG）、错误提示图占位图
- 开发环境运行：
  ```bash
  venv\Scripts\activate
  python app.py
  ```
  启动后监听 `0.0.0.0:5000`，本机访问用 `http://127.0.0.1:5000`，局域网其他电脑访问用本机的局域网 IP。

## 打包成 exe

用 PyInstaller，具体脚本在 `build_tools/` 里。核心注意点：

- 代码里 `get_resource_path()` 用 `sys._MEIPASS` 取打包后的**只读**资源路径（`base.jpg`、`handwrite.ttf`、`index.html` 模板文件走的是这条路径），这个目录程序退出后会被清空，**不能**用来存日志、模板这类需要持久化的数据。
- 日志、模板这类要持久化的文件，用的是 `sys.executable`（exe 自身所在目录），保证程序关闭、重启后数据还在，且不管用户从哪里启动 exe，路径都固定在 exe 旁边，方便查找。

## 后端路由一览（`app.py`）

| 路由 | 方法 | 作用 |
|---|---|---|
| `/` | GET | 返回 `index.html` |
| `/preview` | POST | 根据传入的 text/fields/settings 生成 PDF，存临时文件，返回可在 iframe 里预览的 URL，同时生成一个 `task_id`（关联本次的姓名/住院号，供后面下载 ZIP 时用来命名文件） |
| `/generate` | POST | 跟 `/preview` 类似，生成 PDF 并返回下载链接（目前前端没有调用这个接口，是历史遗留的“原有下载接口”，如果要加“直接下载 PDF”的按钮可以复用它） |
| `/view_pdf/<filename>` | GET | 把临时目录里生成好的 PDF 文件返回给浏览器（用于 iframe 预览） |
| `/download_images/<task_id>/<filename>` | GET | 把指定 PDF 转成多张 JPG 图片，打包成 ZIP 返回下载，文件名格式是 `{姓名}-{页码}-{住院号}.jpg` |
| `/template` | GET | 读取 `template.json`，返回共享模板的 text + settings，前端一打开页面就自动调用这个接口填充文本框 |
| `/template` | POST | 把当前 text + settings 写入 `template.json`，覆盖式保存，局域网内所有人下次打开/刷新页面都会看到最新内容 |

### 关键函数（`PDFGenerator` 类）

- `register_font()` — 注册手写字体到 reportlab，失败会 fallback 成 Helvetica（英文字体，中文会乱码/不显示，所以字体文件缺失是要重点排查的问题）
- `create_pdf_with_preview(text, fields, settings)` — 核心渲染逻辑：
  - 每页先画 `base.jpg` 背景
  - 再画 `fields`（病区/姓名/床号/住院号）到 `settings.fields` 指定的坐标
  - 正文按 `max_width` 自动换行（按标点断句，避免标点开头结尾），逐字加随机抖动（`char_jitter`/`line_jitter`）模拟手写效果
  - 写满一页自动 `showPage()` 翻页，重新画背景和字段

### 文件存储位置逻辑

- **临时 PDF 文件**：`tempfile.NamedTemporaryFile`，存在系统 temp 目录（`tempfile.gettempdir()`），**目前没有清理逻辑**，长期运行会越堆越多（见“已知问题”）
- **日志**：`get_log_dir()` → exe 同级目录下的 `logs/operation.log`，记录“预览 PDF / 查看 PDF / 下载 ZIP / 保存模板”等操作，格式：`时间 | IP=xxx | 操作=xxx | 文件=xxx`
- **共享模板**：`get_template_path()` → exe 同级目录下的 `template.json`，只有一份，JSON 结构：
  ```json
  {
    "text": "正文内容",
    "settings": {
      "font_size": 15,
      "start_x": 64,
      "start_y": 661,
      "line_height": 30,
      "line_jitter": 3,
      "char_jitter": 2,
      "fields": {
        "病区": {"x": 110, "y": 694},
        "姓名": {"x": 190, "y": 694},
        "床号": {"x": 280, "y": 694},
        "住院号": {"x": 450, "y": 694}
      }
    },
    "updated_at": "2026-08-31 10:00:00"
  }
  ```
  注意：模板里**不包含**病区/姓名/床号/住院号这几个字段的具体值，只包含它们打印在纸上的坐标（因为具体值是每个病人不同的，不适合放共享模板里）。

## 前端结构（`index.html`）

没有构建工具，改动直接编辑这个文件即可。

- **Tab 切换**：基本信息 / 文本设置 / 手写效果 / 字段位置，四个 tab 用 `switchTab()` 控制显示隐藏。
- **`settingsConfig` 数组**：定义了哪些数字类设置项（字体大小、坐标、行距、抖动），页面加载时用 `createsettingsConfig()` 动态生成对应的 `<input type="number">`，改这个数组就能增删设置项，不用手写 HTML。
- **`fieldConfig` 数组**：定义了哪些病人信息字段（病区/姓名/床号/住院号）及默认打印坐标，`createFields()` 动态生成对应输入框。改这个数组能增删字段（比如要加“诊断”“主治医生”之类的字段，改这里就行）。
- **`getSettings()` / `getFields()`**：分别收集当前页面上的设置值和病人信息值，组装成传给后端的 JSON。
- **`generatePreview()`**：调用 `/preview`，把返回的 PDF URL 塞进 `<iframe>` 实时预览。
- **`downloadAllImages()`**：调用 `/download_images/<task_id>/<filename>`，触发浏览器下载 ZIP。
- **`loadTemplate()`**：页面打开时（`DOMContentLoaded`）自动调用，从 `/template` 拉取共享模板内容，回填正文文本框和所有设置项。
- **`saveTemplate()`**：点击"保存为共享模板"按钮时调用，把当前正文 + 设置 POST 到 `/template`，覆盖写入服务器。

**目前没有任何本地缓存（localStorage）**，病区/姓名/床号/住院号这些病人信息字段每次打开页面都是空的，需要用户手动输入；正文和排版设置则每次打开都从服务器拉取共享模板。

## 已知问题 / 待办（另见 TODO.md）

- 临时 PDF 文件（系统 temp 目录）没有清理逻辑，长期运行会占用越来越多磁盘空间。
- `/template` 是单一全局模板，没有并发写入保护，如果两个人几乎同时点"保存"，有小概率后保存的会完整覆盖先保存的（对这个工具的使用场景影响不大，但如果以后要做多模板/多用户，需要重新设计存储方式）。
- 没有任何登录鉴权，局域网内任何设备都能访问、修改共享模板、下载病历。
- `/generate` 接口前端目前没有用到，是历史遗留代码。

## 我常见的改动诉求（供 AI 参考，按需删改）

- "加一个字段"（比如诊断、床位医生）→ 改 `fieldConfig` 数组（前端）+ 后端 `draw_header_fields()` 不用改（它是遍历 `fields` 字典通用逻辑，已经支持任意字段名）。
- "加一个排版设置项"（比如页边距）→ 改 `settingsConfig` 数组（前端）+ 后端 `create_pdf_with_preview()` 里用 `settings.get("xxx", 默认值)` 取值。
- "换手写字体/背景图"→ 直接替换 `handwrite.ttf` / `base.jpg`，文件名不变则代码不用改。
- "清理临时文件"→ 需要新增定时任务或在下载完成后删除 temp 目录里的旧 PDF。
